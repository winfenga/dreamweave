feat(build): 应用图标 + Windows exe 打包

## 图标（build/icon.svg + icon-small.svg）

设计：琥珀色斜纹编织 + 中心星芒，对应 DreamWeave / 织梦。
选择编织而非书/羽毛的理由：书太通用，羽毛是上游旧品牌遗留；
交错编织既是名字的字面意思，也是唯一能在 16px 下仍可辨认的几何结构。

两份 SVG，按尺寸切换（这是图标的标准做法，不是妥协）：
- 48px 及以上用细节版：四经四纬一上一下的提花
- 48px 以下用简化版：三条粗带 + 加粗星芒
实测细节版缩到 32px 时每根条带只剩 2~3 像素，交错点全糊成一坨深斑。

生成脚本 scripts/make-icon.mjs：resvg 光栅化 7 档尺寸 + 手写 ICO 容器封装。
resvg 只在构建期用（devDependency），不进运行期 bundle，不破坏「运行期零依赖」。

图标制作中修掉的三处真问题（已写进 SVG 注释，避免以后再踩）：
1. XML 注释里不能出现双连字符（CSS 变量那种双横线写法会让整份 SVG 解析失败）
2. rotate(45 256 256) 配局部坐标 -132..132，整组被平移到画布外，只剩星芒
3. 条带范围 264 旋转后对角线 373 大于菱形 364，四角捅出裁剪边界

## 打包（electron-builder.yml）

目标 portable 单文件 exe + nsis 安装包，x64。

关键配置：
- files 显式包含 resources/：主进程 resourcesDir() 找的是 app.getAppPath()/resources，
  打包后 appPath 指向 asar。少了 task-registry(33)/effect-catalog(74)/prompts，
  对应功能会在真机报「目录不可用」，而开发版一切正常，极易漏检
- signExecutable: false（不是 signAndEditExecutable: false）：
  后者会把「改写 exe 资源」一并关掉，结果 exe 用默认 Electron 图标（实测过）

## 打包版冒烟验证

新增 scripts/smoke-packaged.mjs（6 项）：在打包后的 exe 上跑，确认 asar 内
静态资源真的可读（特效目录 74 条、任务注册表 33 条、file:// 运行）。

顺带纠正一个自己写错的字段名：tasksOverview 返回的是 overview.tasks 而非
overview.items，最初按 items 读导致误判「注册表为空」。

新增命令：npm run icon / npm run pack / npm run pack:installer / npm run verify:packaged
产物：dist/DreamWeave-0.1.0-portable.exe（76.6 MB），图标已嵌入。
